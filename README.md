# 景区资料协作台账：评级结论的证据血缘

服务登记资料来源、字段、原件、使用许可、数据产品与交付凭据，并为评级结论维护可追溯的证据血缘：材料补正与失效按评价项目限定影响，历史结论依据可原样复现，当前结论会明确提示需要复核的项目。示例主体和记录均为虚构，不连接真实文旅部门。

需要 Python 3.10 或更新版本，不依赖第三方包。

运行项目测试：python -m unittest discover -s tests -v。
检查源码：python -m compileall -q exchange。
运行本地演练：python -m exchange --database demo.db。

## 模块职责

- `catalog.py`：登记来源字段和原件；`invalidate` 标记材料失效（保留原件，写入 `valid_to`）。
- `evidence.py`：景区与评价项目登记，材料到评价项目的挂接；影响范围沿挂接传播。
- `lineage.py`：材料补正（corrects，旧材料转 superseded）与补充（supplements）关系及影响范围查询。
- `grants.py` 与 `policy.py`：管理使用边界，交付时按领取方、用途和辖区核对。
- `products.py`：编排资料产品及其输入修订。
- `conclusions.py`：评级结论发布（冻结证据集合与有效区间）、历史复现（replay）、当前可用性与复核提示（status）、修订列表。
- `delivery.py`：出具数据产品或评级结论的交付回执；结论回执含冻结证据快照。
- `audit.py`：记录操作。

## 血缘规则要点

1. 结论发布即冻结：证据摘要、有效区间和集合摘要写入不可变记录，新材料不能进入旧结论，再发布即新修订。
2. 失效不毁史：材料失效或被补正后原件保留，`replay` 可重算并证明历史依据一致。
3. 影响按项目隔离：补正/失效只作用于材料挂接的评价项目，其他项目证据不被牵连。
4. 凭据可区分时态：交付快照同时含发布时冻结区间与材料当前状态，事后失效不篡改已出具凭据。
