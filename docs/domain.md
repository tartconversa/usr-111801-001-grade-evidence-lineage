# 景区资料语义

来源可以是主管部门、景区运营方或合作机构。每份原件有来源、字段说明与摘要，产品修订引用原件，交付时按领取方、用途和来源辖区核对许可。受理人员应能区别来源事实、内部编排和已交付凭据。

当前项目围绕评级结论的证据血缘开展资料协作。正式公告、复核观察和运营材料各有发布主体；示例记录不代表真实景区状态。

## 材料生命周期与有效范围

材料（assets）一经入库其 payload 与摘要即不可变，状态在 `active`、`superseded`（被补正）、`invalid`（失效）之间流转，并以 `valid_to` 记录有效截止。失效或补正只改变状态，不删除原件，因此任何历史结论依据的内容都能原样复现。

材料通过 `asset_item_links` 挂接到评价项目（evaluation_items，隶属景区 sites）。材料出问题时，影响范围沿该挂接传播：只波及挂接的评价项目，不能据此判废同一景区的其他证据。`asset_relations` 记录两类血缘：

- `corrects` 补正：新材料替代旧材料，旧材料转为 `superseded`，必须限定在具体评价项目；
- `supplements` 补充：新材料丰富证据，旧材料保持有效。

## 结论证据集合

评级结论（conclusions）按修订发布。发布时把每条证据的材料摘要、有效区间（`valid_from`/`valid_to`）冻结进 `conclusion_evidence`，并计算整个证据集合的摘要 `evidence_digest`。由此：

- 新材料无法悄悄进入旧结论；重新发布只能生成新修订，旧修订转为 `superseded` 但证据冻结不变；
- `replay` 按冻结清单重算摘要并比对原件，证明历史依据可复现（`evidence_set_intact`）；
- `status` 对照材料当前状态计算可用性：某条证据失效只让对应评价项目进入 `need_review_items`，其余项目保持可用；结论当前不可用时 `usable_now` 为假，明确提示需要复核。

## 交付凭据

交付（deliveries）既支持数据产品，也支持评级结论。结论交付凭据携带发布时的证据快照（含冻结有效区间与材料当前状态），并沿用许可（grants）与策略（policies）闸门。材料事后失效不影响已出具凭据的完整性，快照会如实反映当前状态，受理人可据此区分"当时依据"与"当前可用性"。
